# SNAPSHOT

## 项目身份

RTsql（**v0.2.0**）— 异步协程驱动的高性能嵌入式关系型数据库。以 Tokio 无栈协程为调度核心，实现轻量、便捷、高效的现代数据库系统。

## 技术栈

- **语言**: Rust 2021 edition
- **构建工具**: Cargo
- **异步运行时**: Tokio (rt-multi-thread, macros, sync, time, net, fs, io-util)
- **SQL 解析**: sqlparser-rs 0.44
- **序列化**: serde + serde_json
- **并发原语**: dashmap, lru, tokio-util
- **CLI**: clap 4 (derive/env) + clap_complete 4
- **加密**: argon2 0.6 (Argon2id) + aes-gcm 0.11 (AES-256-GCM)
- **CSV**: csv 1.4
- **校验**: crc32fast
- **测试框架**: criterion.rs (benchmark) + tempfile + rusqlite (对比)
- **格式化**: rustfmt
- **Lint**: clippy
- **随机数**: rand 0.8

## 关键特性

- **轻量**: 单库静态链接，无外部数据库服务依赖
- **便捷**: one-shot CLI、12 个可见生命周期/分析子命令（`rtsql delete <db>` 删库：锁探测同窗口删除、伴生清理、逐文件报告、`--dry-run`；`rtsql checkpoint <db>` 显式落盘：WAL 截断 + checkpoint 位点推进、零工作明示 `no pending work` exit 0；`rtsql check <db>` 只读结构完整性校验：页 census/catalog/数据链/溢出链/三类索引树扫描、error 级损坏逐行报告页位置与语义 exit 1、info 级〔未引用溢出链、恢复后 tail 良性领先〕不改退出码、不修复不修改文件、`:memory:`/`--readonly` exit 2、pending WAL 经纯读恢复会话收敛后再 check、新建零行表即干净〔存量 0x00 head 打开不自愈、首次写入/TRUNCATE 自然转绿〕）；import 输入面（stdin `-` 通道、目标表缺失按 CSV 表头自动建表〔字段猜测 + CTAS 推导矩阵合并、冲突点名拒绝零副作用、首列隐式主键语义〕、`:memory:` import 豁免〔`--key` exit 2〕）；隐藏 shell 补全生成与本机安装脚本；锁等待预算可配置——`--busy-timeout <MS>` global flag/env `RTSQL_BUSY_TIMEOUT`/lib 三通道（默认 5000ms、显式 0 不额外等待、非法值 open 前 exit 2、flag 优先、`:memory:` 接受忽略、`delete` 探测永不等待），并发 one-shot 逐个原子完成；dump 数据链完整性预检（断链库 stderr 一行告警、rc 0 继续、stdout 纯 SQL 不受影响）；dump DDL 仅 INTEGER 主键列输出 `PRIMARY KEY`（存量非 INT PK 表 dump→restore 往返可达）；主命令对缺失库显式拒绝（exit 1 + `rtsql new` 指引、零文件创建，创建通道收敛 `rtsql new`，lib 与生命周期子命令建库/拒绝语义不变）
- **错误面可操作**: 不支持语句/表达式报错点名能力；PG 协议错误按类携带 SQLSTATE（0A000/42601/42P01/42703/42702/58000 兜底归类）；CLI 错误输出渲染 SQLSTATE（文本格式错误行尾 ` [SQLSTATE xxxx]`、`--format json` 错误对象 `sqlstate` 字段无分类时省略，退出码/文案/PG 面零变化）；计划期列解析显式化（未知投影列/未知排序键/列缺失点名）；恢复重放对「WAL 记录引用的表在 catalog 缺失」定向指因（点名表名与可能原因，打开拒绝与不跳过记录语义不变）

## 主要模块边界
