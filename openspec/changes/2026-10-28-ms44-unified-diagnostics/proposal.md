# 统一分级诊断与性能归因

对应路线：`.agents/docs/tasks.md` 的 MS44。来源：I096。约束：M19、M21、M22，以及本 goal 对 M20 的当次变体（见「实施期缺陷」）。

Gate 1 为 PASS。批准来自本次 goal 对 tasks.md 里已写明的 MS44 Outcome、Scope、Non-goals、Stable result、Split signals 的授权，不是跳过。本文件不更新全局里程碑状态，不改 SNAPSHOT，也不把 I096 标成已完成。

## Why

MS44 要求各模块经统一接口报告事件、阶段耗时、等待和资源统计，并且诊断可配置、输出受控、开销有实测。当前只有 `src/profiling.rs` 在 `RTSQL_PROFILING` 存在时，把解析、规划、执行和少数子指标打到 stderr。它不区分锁、I/O、队列和调度等待，不覆盖失败、取消和并发，也没有输出上限。M22 约定的 `rtsql::diagnostics` 尚未落地。MS43 已归档，会话级刷盘和提交等待的责任边界可以采集，不再和生命周期改造混在一轮里排障。

## What Changes

- 增加会话级诊断配置。输出详细程度、观察类别、采集内容三项分开。采集内容至少能分别开关事件、性能统计和详细追踪。性能统计可以在事件和详细追踪都关闭时单独打开。
- 语句路径记录解析、规划、执行；实际发生提交时，把提交记为执行的子阶段。摘要总耗时等于该语句根阶段的包含耗时，不把父子阶段相加后再当作总耗时。
- 在已有的提交等待和文件页读取上区分计算、锁、I/O、队列和调度等待。同一次提交的刷盘样本进入该语句的摘要，不进入并发的另一条语句。
- 成功、失败和语句 future 被放弃都会结束这条语句的记录。取消之后的行可见性仍按 `statement-cancellation-outcome`。
- 每条语句的事件和追踪样本有上限，会话保留的已结束摘要也有上限。超出后停止追加并保留超出计数。统计汇总继续更新。诊断投递在语句执行过程中不写 stderr。stderr 上的诊断文本只在 SQL 结果已经确定之后写出。慢的 stderr 可以推迟调用返回，不改变 SQL 结果。
- 在同一条已有语句负载上测量关闭、只开性能统计、详细追踪三种配置的耗时。三次 SQL 结果相同。不设三者差值的数值上限。
- `RTSQL_PROFILING` 的默认关闭和三段计时输出保持。`pipeline-stage-decomposition` 的「三段顶层计时观测」不改。现有用户可见 stderr 告警保持原文，包括恢复路径上的 `[recovery]`。

无 **BREAKING**。默认配置不采集、不写出新的诊断 stderr。

## Capabilities

### New Capabilities

- `unified-diagnostics`：会话级诊断的配置、阶段与等待口径、同一次语句的异步样本归属、输出上限，以及诊断不改变 SQL 结果和既有 stderr 告警。

### Modified Capabilities

无。`pipeline-stage-decomposition` 的三段计时、`statement-cancellation-outcome` 的取消结果、`error-reporting` 的 SQLSTATE 都不改。新规格只增加诊断观察，并写明上述结果保持。

## Impact

- 代码：新建 `src/diagnostics.rs` 并在 `src/lib.rs` 导出。`src/database.rs` 增加会话配置和已结束摘要的持有（私有字段，克隆共享）。`src/pipeline.rs` 在语句入口按配置记录阶段。`src/transaction/manager.rs` 的提交等待、`src/wal/buffer.rs` 的刷盘、`src/storage/file_storage.rs` 的文件页读取，只在该语句正在采集时记录等待。`src/profiling.rs` 继续提供 `with_profiling_scope`、`is_profiling_enabled` 和既有 stderr 表；`is_profiling_enabled` 仍只看环境变量。
- 不改：SQL 文本、SQLSTATE、事务提交或回滚条件、磁盘格式、checkpoint 九步、WAL 刷盘单飞、`append_commit_and_wait` 的 `Ok(())`。不新增 crate 依赖。不新增 CLI 参数、SQL 语法或网络协议字段。
- 测试：新增 `tests/diagnostics_facade_test.rs`、`tests/diagnostics_statement_test.rs`、`tests/diagnostics_wait_test.rs`。既有 `tests/recovery_bounded_read_test.rs` 对 `[recovery]` 的断言保持。收尾全量按 M19 分批串行，整个 change 只跑一次。
- 关联：MS44；I096；M19；M21（会话状态仍归 `Database`，诊断模块不反向依赖各层）；M22（门面、记录模型和「只观察」）。

## 需求

1. 输出详细程度、观察类别、采集内容分开配置。性能统计可以单独开启。默认全部关闭。分级名称为 Error、Warn、Info、Debug、Trace。
2. 未命中计划缓存的语句分别记录解析、规划、执行。提交是执行的子阶段。语句总耗时等于根阶段包含耗时。缓存命中不为这次执行记录解析和规划。
3. 详细追踪下，提交等待区分 Lock、Queue、Io、Schedule；文件页读取记为 Io；其余阶段时间记为 Compute。同一摘要内，内层等待不重复加进外层。
4. 刷盘任务上属于某次提交的等待样本进入该语句摘要。并发语句按各自 SQL 文本区分。公开摘要没有操作标识、运行标识或内容哈希。
5. 成功、错误返回、future 在完成前被放弃，都会结束记录。错误文本和 SQLSTATE 不变。取消不改变既有行可见性。
6. 单条语句事件上限默认 64，会话保留的已结束摘要默认最多 32 条。超出后保留计数，统计汇总继续。执行过程中的投递不写 stderr。
7. 关闭、只开性能统计、详细追踪三种配置都有耗时记录，SQL 结果相同，无数值门槛。
8. `RTSQL_PROFILING` 未设置时不输出旧的三段计时表；设置且会话配置保持默认时，stderr 仍含 parse、plan、execute。默认诊断配置下，既有 stderr 告警原文仍在。
9. 整个 change 收尾时按 M19 分批串行跑一次全量。缺一批不得声明全量通过。

## 不做

- 用新增日志条数代替上述能力。
- 规定未测量的零开销，或给三种配置的耗时差设定通过上限。
- 做实际性能优化，包括改执行计划、组提交、缓存策略或 I/O 路径。
- 建独立监控进程、远程采集、持久化诊断库或可视化界面。
- 用诊断输出代替 SQL 结果、错误文本或行可见性断言。
- 把操作上下文、操作标识、运行标识或内容哈希用作测试或证据的通过条件。
- 迁移 table_manager、recovery、index_manager、network、drop_index、data_page、database 上现有的 stderr 告警。那些告警保持原文。
- 改事务结果、SQLSTATE、取消合同、磁盘格式、checkpoint 九步或刷盘单飞。
- 给全部锁和全部 await 加计时。
- 预建「修复尚未发现的缺陷」的 Iteration。

## 场景草图

| # | 类别 | 前置 | 动作 | 可观察结果 | 失败边界 |
|---|---|---|---|---|---|
| S1 | Happy | 只开性能统计，观察语句阶段 | 执行一条成功查询 | 进程内摘要有阶段耗时，无逐条追踪样本；查询结果与关闭诊断时相同 | 结果变化或出现逐条样本即失败 |
| S2 | Happy | 详细程度关闭，性能统计打开 | 执行一条成功语句 | 进程内摘要仍有阶段耗时；这次执行不写出新的诊断 stderr | 把「关闭输出」做成「停止采集」即偏离三项分离 |
| S3 | Happy | 详细追踪打开 | 成功插入并提交 | 摘要有执行阶段和提交子阶段；总耗时等于执行的包含耗时；随后查得到该行 | 总耗时等于父子相加，或行不可见 |
| S4 | Happy | `RTSQL_PROFILING` 已设置，会话配置保持默认 | 执行一条未命中缓存的语句 | stderr 含 parse、plan、execute | 旧表消失即改变既有计时出口 |
| S5 | Sad | 性能统计打开 | 执行无法解析的语句 | 摘要状态为失败并含解析阶段；错误文本和 SQLSTATE 与关闭诊断时相同 | 改错文本或 SQLSTATE |
| S6 | Sad | 性能统计打开 | 隐式插入的 future 在提交前被放弃，再执行下一条写语句 | 被放弃语句的摘要为取消；该行不可见 | 用摘要代替行可见性，或取消路径把行提交 |
| S7 | Edge | 事件上限为 1，详细追踪打开 | 执行一条有多个阶段的成功语句 | 超出计数大于 0；阶段汇总仍在；SQL 结果不变 | 无上限地保留样本，或为了限量改结果 |
| S8 | Edge | 性能统计打开，观察类别不含语句阶段 | 执行成功查询 | 摘要没有解析、规划、执行；查询结果不变 | 类别过滤失效 |
| S9 | Edge | 详细追踪打开，缓冲池里还没有该数据页 | 查询要从文件读页 | 摘要含 Io；查询结果与关闭诊断时相同 | 把命中缓存的内存访问记成 Io |
| S10 | 组合 | 同一会话、两条 SQL 文本不同的插入并发提交 | 两条都成功 | 每条摘要只有自己的 SQL 文本；没有操作标识字段；两行都可见 | 样本串句，或靠标识字段判定通过 |
| S11 | 组合 | 只开性能统计 | 成功查询 | 有执行阶段，没有提交子阶段 | 给不写数据的查询编造提交 |
| S12 | 错误 | 详细程度为完整 | 成功查询 | 返回行与关闭诊断时相同，行内没有阶段名或等待类别 | 把诊断文本写进结果集 |
| S13 | 兼容 | 诊断配置默认 | 运行会写出 `[recovery]` 的既有恢复测试；收尾再按 M19 分批全量 | stderr 仍含 `[recovery]`；全量每批退出码 0 且 failed 为 0，目标对账无缺无重 | 借诊断收走告警，或缺一批仍声明通过 |

## 回滚

改动在 change 分支的诊断模块、会话字段、语句与提交等待接线和新增测试。回滚是还原或放弃该分支。主分支在合并前不被改写。无格式迁移，无新的磁盘字段。默认配置下的 SQL 结果和既有 stderr 告警与改前相同，因此不需要数据回放。

## 默认假设

下列假设闭合场景缺口。它们不扩大 MS44 的 Scope，不把诊断输出当成测试身份，不改变事务结果，也不做成独立监控平台。

1. 只建这一个 change。Split signals 要求采集、关联和输出留在同一套能力里验证。本范围没有诊断专用存储、远程平台或可视化。能分开验证的部分用 Iteration，不建第二个目录。
2. 分级名称定为 Error、Warn、Info、Debug、Trace。成功阶段结束为 Info，失败为 Error，取消为 Warn。依据：M22 把名称留给 MS44；I096 要求分级，但没有预定依赖或外部日志框架。
3. 配置放在会话上，由 `Database` 持有。不新增 CLI 参数、SQL 语法或 crate。`RTSQL_PROFILING` 仍是旧三段计时表的开关，`is_profiling_enabled` 仍只读该变量。依据：M21 将会话状态归 `Database`；M22 禁止把输出决定放回各模块；现有规格要求该开关默认关闭。
4. 进程内摘要是观察口。公开字段只有严重级别、类别、消息和数值数据。消息里可以有截断后的 SQL 文本，用来区分测试自己提交的语句。没有操作标识。依据：Non-goals 禁止把操作上下文用作测试或证据身份；I096 要求关联同一次产品操作，关联发生在门面内部。
5. 单条语句事件上限默认 64，会话已结束摘要默认保留 32 条并丢弃最旧的。依据：Scope 要求明确限量和超量处理；不把保留策略做成可检索的监控库。
6. `report` 只写入内存摘要。stderr 在 SQL 结果确定之后、调用返回之前写出。慢 stderr 可以推迟返回。不另起后台写出任务。依据：I096 要求说明慢输出是否阻塞数据库；Non-goals 排除独立监控平台。阻塞的是返回，不是事务结果。
7. 等待只加在这些已有点上：提交路径的会话闸门和刷盘闸门（Lock），`append_commit_and_wait` 里等待刷盘完成的那次等待（Queue），完成该等待的那次 `write_batch`（Io），从通知刷盘到刷盘任务开始处理这批的间隔（Schedule，可以为 0），以及 `FileStorage::read_page`（Io）。解析阶段没有这些等待，记为 Compute。依据：Scope 要求区分这几类等待；Non-goals 不要求给全部锁加计时。
8. 同一次 `write_batch` 释放的每个提交，其摘要都包含这整段 I/O 耗时。这些数不得跨语句相加当作进程级 I/O。依据：I096 禁止父子重复相加；组提交是一次共享 I/O，不是第二个父阶段。
9. 不迁移其余直接写 stderr 的告警。`profiling.rs` 的旧表留在 `RTSQL_PROFILING` 路径上。依据：M22 要求按域迁移，并要求用户可见告警的有无变化写进规格；本 Scope 的闭环是采集、关联和输出，收走 `[recovery]` 等告警会改变已有行为。
10. 三种开销只记录耗时和 SQL 结果是否相同，不设差值上限。工作负载沿用 `benches/pipeline_stages_bench.rs` 的单行查询形态，判定放在 `cargo test`，不改 criterion 的通过条件。依据：Non-goals 拒绝未测量的零开销承诺；Scope 要求复用已有基准，而不是新的测量框架。
11. 失败场景用无法解析的语句。取消场景用丢弃 future。不新增失败注入点。依据：现有 `write_batch` 失败已经规定仍返回 `Ok(())`，本变更不改那条合同。
12. 本 goal 对 M20 的覆盖只写在「实施期缺陷」，不预建修复 Iteration。
