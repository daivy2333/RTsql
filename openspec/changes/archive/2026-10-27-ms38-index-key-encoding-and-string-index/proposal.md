# 索引键编码评估与字符串二级索引

## Why

任务路线中的 MS38 承接 I024 和 I085 前半。现有模型 M03 记录固定 32 字节 Key；`sql-secondary-indexes` 规格仅接受单列 INT 非唯一索引，字符串等值查询缺少对应能力。短键空间收益尚无本批实测，不能把历史约 70% 的估算当作采用新格式的依据。

前置里程碑 MS37 已完成。用户于 2026-10-27 指令「很好，规划下一个ms到change」，授权将 MS38 展开为变更计划；尚未授权实施。

## What Changes

| 需求 | 目标与验收方向 |
|---|---|
| R1 编码评估 | 比较现有定长布局、保序变长编码与前缀压缩方向，实测索引页数、缓存命中及读写吞吐；先证明逻辑顺序、相等性与恢复一致性，再给出采用或保留现布局的结论。 |
| R2 单列字符串索引 | 在现有 INT 能力上增加声明为字符串类型的单列非唯一二级索引，覆盖存量回填、重复值、空字符串与多字节 UTF-8。具体 SQL 类型映射由调查确认。 |
| R3 等值查询 | 字符串等值查询通过既有 EXPLAIN 面可观察计划；结果与无索引扫描严格相等，包含投影、重复值与 NULL 的既有语义。 |
| R4 生命周期一致性 | INSERT、UPDATE/rekey、DELETE、UPSERT/REPLACE、回滚与取消回收之后，条目与存活行一致；失败不改变已提交内容。 |
| R5 持久化与兼容 | 干净重开、未决 WAL 恢复后结果一致，DROP INDEX 后回落扫描；保留受支持旧库与 INT/PK/唯一索引行为。 |
| R6 存储安全回归 | 如采用新条目布局，同步覆盖页级判界、分裂/合并、释放、完整性检查与恢复读取，不沿用不适合新布局的固定长度判据。 |

这是范围与场景草案，未据此宣称实现可行或执行就绪。实际代码调查、设计、任务定义和首轮执行上下文须在需求确认后完成。

## 范围假设，用户已确认

2026-10-27，用户选择「按草案继续调查与规划（推荐）」；Gate 1 通过。以下保留需求确认时的范围，调查后具体化见本节末尾。

1. 先交付编码评估，再按结果选择采用新编码或保留现布局；不预先承诺必须改格式，也不把变长整数天然视为保序编码。
2. 字符串能力以单列、非唯一、等值查询为最小范围；比较沿用既有 SQL 语义，不增加排序规则或隐式类型转换。NULL 不入索引，重复字符串允许并存。
3. 旧库继续可读写且已提交数据不丢失，不以全库自动迁移作为默认方案。任何新格式写入及其回退策略都在最终设计中明确后再审计。
4. 不预定字符串最大字节数、长值的索引策略、编码采用阈值或兼容布局。调查必须在 Gate 2 前给出这些实质问题的明确答案；需要缩减需求时先更新 RTM 并取得批准，不交由 Act 决定。
5. 字符串比较必须区分完整值，尤其是共享长前缀、尾部零字节与多字节边界；禁止截断后静默合并不同值。对于支持域外输入，拒绝或回落策略必须在设计中明示，不得漏行或返回错误匹配。

调查后的具体化（2026-10-27 用户批准详细计划）：字符串声明沿用 ColumnType::String；只在完整编码可容纳时入树，超出物理容量的合法字符串继续写入并按完整字面量扫描，不限制行字段长度、不截断、不使用摘要键。保留 fixed32 时采用零转义加终止符、编码长 <=32 字节。首轮只做真实页原型评估，完整实施路线分为四轮，不在无实测时切生产格式。

布局选择已关闭（2026-10-27，本次执行 goal）：保留现有 32 字节固定键，采用 fixed32。两种候选的热读没有同时守住已批准的 5% 吞吐线；页数和写、冷读收益不能单独切换生产格式。不采用 ordered-variable 或 prefix-restart，不降低筛选门槛，不重跑 Criterion。

上述 Gate 2 按所属执行轮判断：首轮没有生产格式写入，编码原型、负载、筛选条件和停止边界已明确；后续实际树方案必须在其所属轮进入 Gate 2 前闭合。首轮结果不能替代该决策。

## Scenario Sketch

| 场景 | 前置状态 | 动作 | 结果及失败边界 |
|---|---|---|---|
| S01 编码正确性 | 整数边界、空串、UTF-8、共享前缀、含零字节样本 | 对候选编码进行比较与往返 | 逻辑顺序和相等性不变；不满足者不能进入性能采用候选。 |
| S02 编码取舍 | 正确性成立的候选与现布局、同一负载 | 比较页数、缓存命中、读写吞吐 | 按已批准的筛选门槛形成候选建议；生产采用还须通过实际树验证，无收益不能自动改格式。 |
| S03 存量建索引 | 含重复字符串、NULL、空串与 UTF-8 的表 | CREATE INDEX，执行等值查询 | 支持域内建索引成功，全部命中与建索引前相等，NULL 不因建索引改变结果。 |
| S04 路由与投影 | 已建字符串二级索引 | EXPLAIN 与单列、乱序多列、通配、聚合等值查询 | 路由可观察，表头与行对应，重复行不丢失、不多发；EXPLAIN 不执行查询。 |
| S05 长度与前缀边界 | 两值共享前缀；长度位于物理键边界两侧 | 建索引、查询及后续写入 | 按最终批准的支持域执行；完整值不可混同，不允许静默截断、漏索引或损坏。 |
| S06 持续写入 | 已有字符串索引与存量行 | INSERT、字符串改值、字符串与 NULL 双向转换、DELETE | 新旧键可达性与存活行一致；重复值其他行不受误删。 |
| S07 多步回滚 | 显式事务修改多个字符串键 | INSERT/UPDATE/DELETE 后 ROLLBACK | 行与条目回到事务前状态；再次使用相同键可成功。 |
| S08 冲突和失败 | 已有 PK/唯一约束与字符串二级索引 | UPSERT/REPLACE，以及构造失败写语句 | 成功路径维护全部受影响索引；失败路径不改变已提交行与条目。 |
| S09 取消与超时 | 索引写单元在途 | 丢弃语句 future 或 timeout 到期，再触发既有回收 | 沿用提交前取消与提交后未送达的结果约定；不留半写结构或残留键。 |
| S10 干净重开 | 建索引并完成增删改后关闭 | 重新打开，查询与完整性检查 | 索引内容与行一致，完整性无 error。 |
| S11 崩溃恢复 | 已提交字符串写入，仍有未决 WAL | 不 close 结束后重新打开 | 已提交行恢复，索引重建后等值结果一致；未提交行不可见。 |
| S12 删除与释放 | 已建字符串索引且存在其他索引 | DROP INDEX 后查询、重开、检查 | 计划回落扫描，表与其他索引不变，释放页遵循既有持久化边界。 |
| S13 拒绝边界 | 重名、缺表/列、不支持类型或修饰、显式事务 | 执行不支持的建索引形式 | 沿用既有分类点名拒绝且零副作用；不得因支持字符串而扩大其他语法。 |
| S14 组合运行形态 | 受支持旧库、内存库、只读与加密库 | 在相应形态执行合法查询或写入 | 沿用各运行形态的权限、文件与恢复语义；仅测试当前能力可达的组合。 |
| S15 损坏条目 | 新布局条目长度或槽边界损坏 | 查询/写入、check、释放 | 读写明确错误，检查报告，释放按既有尽力而为语义告警跳过；不 panic。 |

场景扫描已覆盖正常、失败、边界、多步组合，以及取消、并发和兼容。并发继续受既有索引写单元、写侧闸门与无并发未提交回填窗口的约束；不增加新的并发 DDL 承诺。

- 清理现存暂存区或其他归档产物差异。
