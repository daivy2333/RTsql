# 无键行的旧版本能被既有 GC 回收

来源：里程碑 MS46（`.agents/docs/tasks.md`，Status ready），承接 I038（`.agents/memory/improvements.md`）。关联约束：M10、M19、M23。配方：R48（`.agents/runbooks/m19-batched-full-regression.md`）。

Gate 1 为 PASS。批准来自本次 goal。用户原话：「规划并实施ms46，要求遵守各种规范，尤其是多批次串行测试规范」。这句原话在检查通过后，视为对 MS46 范围内需求、范围和计划的批准。本文件不更新里程碑状态，不改 SNAPSHOT，不改 I038 的台账正文，不改 `openspec/specs/` 里的权威正文。

I038 的旧文字仍写「未承诺、未排期、量化先行」。承诺范围以 MS46 为准。MS46 的 Outcome 没有测量门，本次不把「量化先行」当作采纳条件。

## Why

`TableMeta::gc_table` 只从主键索引的 `scan_all` 进入版本链。键位没有 B-Tree 键的行不在这个索引里，它的旧版本一直留在数据页上。MS46 要补的是这条链能被同一次 GC 看见，并按已经在用的判定和释放规则回收。

调查结论：做到这一点不用改 MVCC 快照可见性，也不用改空闲页的提升条件。MS46 的拆分信号没有触发。

## What Changes

- 同一次 GC 到达无键行的版本链。已提交、且不是该链链头的版本被回收。链头和尚未写入 commit 的版本留下。
- 带键行仍从主键索引当前指向的版本走链，判定和释放函数不变。因删除而离开索引的带键链不进入这次回收。回滚后仍然有效的版本不被回收。
- 释放仍是现有的槽删除。溢出链仍进入待释放集合，提升之前不能被分配。
- GC 的返回值仍是本次删掉的版本数，无键回收计入这个数。不新增 SQL，不新增调度。

无 **BREAKING**。不改磁盘格式，不改索引条目格式，不改快照判定，不改空闲页生命周期。

## Capabilities

### New Capabilities

- `keyless-version-gc`：无键行版本链进入既有 GC，以及带键行 GC 合同在这次扩展下保持。域路径 `openspec/specs/keyless-version-gc/`。

### Modified Capabilities

无。`overflow-page-storage` 里「旧版本 slot 被 GC 回收时溢出链一并释放」的要求保持，本次只让无键旧版本也走到同一释放。

## Impact

- 代码：`src/storage/data/table_manager.rs` 的 `TableMeta::gc_table`。无键走查读数据页链、版本头和元组，删除调用现有的 `delete_tuple_from_data_page`。
- 不改：`Snapshot` 的可见性函数、索引页格式、`free_page` / `complete_free_release` / `promote_free_releases` 的规则、WAL 记录、刷盘策略、GC 的调用方（仍是直接调用 `gc_table`）。
- 测试：`tests/gc_test.rs` 增加无键链、带键合同和走查失败用例；`tests/overflow_page_test.rs` 增加无键旧版本的溢出释放用例。既有三个带键 GC 用例的断言不改。收尾全量按 M19 与 R48 分批串行，整个变更只跑一次，放在最后一个 Iteration。
- 关联：MS46；I038；M10；M19；M23；R48。

## 需求

下列条目是本次批准的需求。

1. 键位不可入索引的行，其旧版本链能被 GC 回收。
2. 可见性判断和释放规则与已有 GC 相同。仍由该规则留下的版本不回收。
3. 带键行的既有 GC 合同不变。
4. 不提高 GC 速度，不改变 MVCC 可见性，不改索引格式、空闲页生命周期或刷盘策略，不做节点级锁、分配器或 clone 消除。
5. 全量回归若写入验证，按 M19 与 R48 分批串行。缺一批不得声明全量通过。
6. 实施期新发现的实质缺陷按 M23 在发现后追加 Iteration。本次不预建。

「与已有 GC 相同」的落地：链头不回收；`commit_tx_id()` 为 `None` 的版本不回收；`commit_tx_id()` 为 `Some` 且不是链头的版本回收。不另按快照或活跃事务留下旧版本。依据是 `gc_table` 现有谓词，以及 `tests/gc_test.rs` 里 `test_gc_preserves_uncommitted_versions` 的断言（未提交链头留下，已提交前驱被回收）。该用例上方的注释写着 `cleaned_count == 0`，与断言不符；合同以断言和实现为准。

## 不做

- 不改 `Snapshot::is_visible` 及读路径的可见性。
- 不把已删除带键行的旧版本纳入回收。那些版本今天就不在索引走查里。
- 不新增 VACUUM、自动 GC 或别的 SQL。
- 不为 GC 写 WAL，不改刷盘，不在 GC 里维护索引条目。
- 不改 `delete_tuple_from_data_page` 的释放顺序，不改空闲页提升条件。
- 不做 MS47，不改其他里程碑。
- 不新增身份证明机制或判定层。
- 不修改 `openspec/specs/` 的权威正文。规格增量只放在本变更的 delta。
- 不预建「修复尚未发现的缺陷」的 Iteration。
- 不把 I038 的「量化先行」写成采纳门或测量任务。

## 场景草图

| # | 类别 | 前置 | 动作 | 可观察结果 | 失败边界 |
|---|---|---|---|---|---|
| S1 | Happy | 整数主键行已提交，并有两次已提交的非键更新 | 再把主键更新为 NULL 并提交，然后调用 GC | 返回的回收数等于这个链上除新链头以外的已提交版本数；`SELECT` 只看到 NULL 键和最后一次非键值；被记下的旧 `RowId` 读取为 `SlotNotFound` | 回收数为 0，或 `SELECT` 看不到当前行，或旧槽还在 |
| S2 | Happy | 已提交整数主键行 | 在未提交事务里把主键改为 NULL，然后调用 GC | 回收数至少为 1；未提交的 NULL 链头在该事务的 `SELECT` 里仍可见；旧 `RowId` 为 `SlotNotFound` | 把未提交链头删掉，或把已提交前驱留下 |
| S3 | Edge | 表里只有一行 NULL 主键 | 调用 GC | 回收数为 0；`SELECT` 仍返回该行 | 唯一版本被删 |
| S4 | Edge | 表里有两行 NULL 主键 | 调用 GC | 回收数为 0；两行都还在 | 两行被当成一条链删掉 |
| S5 | Happy | 无键链头的前驱是已提交超页版本，链头没有索引条目 | 调用 GC，再按现有溢出用例观察分配 | 回收数为 1；链页在提升前分配不到；提升后分配到的是这批链页 | 为无键链另定一套可分配时机 |
| S6 | 兼容 | 带键行有已提交旧版本 | 调用 GC | 现有三个带键用例的断言仍成立；最新版本仍可按当前键读到 | 为了无键走查改这些断言 |
| S7 | 兼容 | 带键行有旧版本，然后按主键删除并提交 | 调用 GC | 回收数为 0；删除前记下的版本槽仍能读到；`SELECT` 没有该行 | 把已删除带键链的旧版本收掉 |
| S8 | 兼容 | 已提交带键行；一次更新已回滚 | 调用 GC | 回收数为 0；`SELECT` 仍是回滚前的值 | 回滚后的有效版本被删 |
| S9 | 组合 | 同一张表里有一条带键链和一条无键链，都有已提交旧版本 | 调用一次 GC | 两条链的旧版本都按各自规则回收；两个链头都还能读到；`SELECT` 同时看到带键当前行和无键当前行 | 只处理其中一条，或把另一条的链头删掉 |
| S10 | Sad | 数据页链的 `next_page_id` 指向自己，页上有无键行 | 调用 GC | 返回 `internal error`，文案点名该表并含 `data page chain cycle`；该无键槽仍在 | 走查不返回，或先删掉无键槽再报错 |
| S11 | Sad | 无键链头指向版本 A，A 的后向指针指向 A | 调用 GC | 返回 `internal error`，文案点名该表并含 `version chain cycle`；链头和 A 的槽都还在 | 走查不返回，或已经删了 A |

## 回滚

改动在变更分支的 `gc_table` 与上述两个测试文件，加上本变更的规格 delta。回滚是还原或放弃该分支。主分支在合并前不被改写。无格式迁移。放弃后，无键行的旧版本回到现在的行为：GC 看不见它们。带键行的 GC 与放弃前相同。

## 默认假设

这些假设只闭合 MS46 原文没有逐字写下、但不改变 Outcome 的判定细节。

1. 链头是数据页上没有被任何「创建者事务 id 不为 0」的版本之后向指针指向、并且自身不是删除墓碑的槽。这与 `table_has_live_rows` 用来识别活链头的规则相同，也与索引里「当前指向的那个版本」对应。依据：带键更新会把索引改到新版本；回滚把索引指回仍有效的版本，并把被放弃的版本标成 `create_tx_id = 0`。
2. 「键位不可入索引」是链头元组的主键值 `Value::to_key()` 为 `None`。主键列下标用 `TableMeta.pk_index`。元组经现有 `read_tuple_from_data_page` 读出（含溢出装配），再用 `deserialize_row`。键位 `to_key()` 为 `Some` 的链头留给索引走查。
3. 无键链上的旧版本即使曾经有整数键，也按无键链回收。键位改成 NULL 时索引条目已经删掉，这些旧槽不再是索引当前指向的版本。
4. 数据页链成环、或从无键链头走出的版本指针成环，用 `StorageError::Internal` 点名表。收集阶段发现环时，本次不删除任何无键版本。带键索引走查若已经删过，不回滚。槽数越界或槽负载越界返回现有的损坏数据页错误，不跳过。短于版本头或版本头无法解析的槽跳过，与 `table_has_live_rows` 相同。
5. 观察 GC 使用 `TableMeta::gc_table`，因为没有 SQL 入口。行是否仍可见，能走 SQL 的用 `Database::execute_sql` 或同一显式事务里的 `execute_in_tx`。依据：`Database::get_table` 与 `buffer_pool` 是现有公开字段。
