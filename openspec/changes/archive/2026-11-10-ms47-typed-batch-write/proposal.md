## Why

里程碑 MS47（`.agents/docs/tasks.md`）要先测量当前引擎上逐行插入占端到端写入的比例，再决定是否交付一条可复用的类型化批量写入入口。入口若存在，后续导入批次和 CSV 去掉逐行 SQL 文本都复用它，不能各做一条写路径。入口的失败语义已经定为整批回滚。

来源是 I021。I077 的导入攒批提交和持锁窗口、I083 的 CSV 有界读取不在本次。

## What Changes

- 用已交付的统一诊断，在现有 100 行逐行插入基准的语句形状上测量。分子是这些插入语句的执行阶段独占时间之和，分母是这些语句的语句总耗时之和。比较使用整数：`执行阶段独占纳秒 × 10 >= 语句总耗时纳秒` 为达到 10%。
- 达到 10%：新增 `Database::insert_batch`。类型检查、约束、索引维护和失败回滚与逐行 `INSERT` 一致。任一失败则整批回滚。不提供部分成功。
- 低于 10%：不新增入口，不改产品代码。测量数字和「不建入口」写入本变更的执行记录。
- 两种结局都不把 import、CSV、分配器、clone、节点锁、io_uring、组提交、代价模型或 JOIN 重排带进来。

采纳门槛来自本次目标里已经写死的委托，不在看到数字之后改动。MS32 的 10% 比的是新路径是否比旧路径快；本次比的是旧的逐行插入工作在写入语句里占多少。

### 场景草图

1. 测量。前置：文件库，表 `bench (id INT PRIMARY KEY, name STRING, value INT)` 已建好，诊断只开性能统计，摘要上限 100。动作：执行与 `benches/common/mod.rs` 的 `insert_rows` 相同的 100 条单行 `INSERT`。结果：100 条成功摘要，测试打印 `total_ns` 与 `execute_exclusive_ns`，表中有 100 行。失败边界：总耗时为 0、缺少 parse/plan/execute/commit，或执行阶段独占加提交包含不等于执行阶段包含时，测量无效，不得当成低于 10%。
2. 裁定。前置：上一场景的两个纳秒数。动作：做整数比较。结果：大于等于 10% 记「建入口」，小于 10% 记「不建入口」。失败边界：乘法溢出时停止，不记成未达标。
3. 批量成功。前置：已裁定建入口，表上有二级索引。动作：`insert_batch` 写入多行全宽 `Value`。结果：受影响行数等于行数，查询和索引查找与同值的多行 `INSERT` 一致。
4. 整批回滚。前置：批次中后一行主键冲突。动作：`insert_batch`。结果：错误与同值多行 `INSERT` 相同，本批每一行都不可见，索引没有本批的新条目。
5. 计划期拒绝。前置：表不存在、目标是视图，或某一行宽度与列数不符。动作：`insert_batch`，包括空切片打到缺表或视图上。结果：错误文本和 SQLSTATE 与对应的 `execute_sql` 插入相同，表和索引不变。
6. 空批次。前置：表存在，`rows` 为空。动作：`insert_batch`。结果：`AffectedRows(0)`，行数不变。只读会话同样返回 0，不打开隐式事务。
7. 显式事务。前置：`begin` 之后 `insert_batch` 成功，再 `rollback` 那个显式事务。结果：批量写入的行仍然可见。批量入口不加入显式事务。
8. 未达标。前置：测量比例小于 10%。动作：结束本次实现。结果：库上没有 `insert_batch`，变更产物里有测量数字和「不建入口」。
9. 保持导入。前置：未改 `src/cli/lifecycle.rs`。动作：不把 CSV 或 import 改到新入口上。结果：导入仍是逐行 SQL。即使入口落地，适配也不在本次。

### 已经由里程碑选定的行为

- 先测量，再决定入口。当前这一轮只做测量和裁定。
- 大于等于 10% 才实现入口；小于 10% 不实现。
- 入口与逐行写入使用同一套类型检查、约束、索引维护和失败回滚。
- 整批失败则整批回滚。部分成功要先回到需求裁定，本次不实现。
- 测量使用统一诊断和现有基准，不新建判定层、身份证明或专用审计工具。

### 计划收束的口径

里程碑没有逐字写下探针和函数签名。下面四条按现有诊断合同和现有插入基准收成可执行定义，写在 `design.md`。它们不是另一次用户表态。

- 负载是现有 `rtsql_insert_100` 的 100 条单行插入。分母是诊断摘要的语句总耗时。分子是执行阶段独占时间，提交子阶段不计入分子。
- 入口是 `Database::insert_batch(table, rows)`。`rows` 的每一行是目录列序上的全宽 `Value`。不接受列清单、`DEFAULT` 填充或 `ON CONFLICT`。
- 空切片在表存在且不是视图时返回 0，不调用 `begin`。
- 表名按 Rust `to_lowercase` 当作一个目录名，不按 `.` 拆成附加库路由。

## Capabilities

### New Capabilities

- `typed-batch-write`：一百条逐行插入的占比测量，以及达标时 `insert_batch` 的写入、拒绝和整批回滚。未达标时不新增该入口。

### Modified Capabilities

- 无。`execute_sql` 的插入、导入和 CSV 保持现状。

## Impact

- 测量只加测试，不改产品代码。
- 达标时的代码落点：`src/database.rs` 新增 `insert_batch`；非空且通过前置检查后调用 `pipeline::execute_stage`。`InsertExecutor` 的门序不复制一份。
- 测试：新增 `tests/typed_batch_write_test.rs`。
- 不改文件格式，无数据迁移。
- 引用：MS47、I021、M21。M19 的「定向测试可用默认并行度」不用于本次；本次每次测试调用都带 `--test-threads=1`。全量不在本变更的任何一轮里跑。

## 回滚

未达标时没有产品改动，无需回滚。达标后的入口没有格式变更；若后续要撤掉，删除 `insert_batch` 及其测试即可，已有 `execute_sql` 插入不受影响。
