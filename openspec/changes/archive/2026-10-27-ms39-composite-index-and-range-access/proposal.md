# 组合二级索引与范围访问

## Why

里程碑 MS39 承接 I085 后半。MS38 已交付字符串单列非唯一二级索引，并保留 32 字节定长键。组合索引仍在计划期被拒绝，范围谓词仍走全表扫描。I085 的稳定结果是整条能力关闭，所以本变更同时交付组合键和范围路由，结果与全表扫描严格相等。

## What Changes

- 在 INT 与字符串列上创建多列非唯一二级索引。键仍是 32 字节。放不下的值不入树、不截断，查询改走完整值扫描。
- 新的单列 INT 索引使用符号位翻转后的 8 字节编码，使字节序与有符号数值序一致，从而可以做范围扫描。已经存在的单列 INT 索引保持原来的大端字节，等值查询不变，范围查询继续扫描。
- 字符串索引的编码不变。范围查询走索引中的有序键，并补上因超长而未入树的行，结果与全表扫描相同。
- 主键、UNIQUE、表达式索引、部分索引和 `CREATE UNIQUE INDEX` 保持现状。

## Capabilities

### New Capabilities

无。

### Modified Capabilities

- `sql-secondary-indexes`：开放组合二级索引和范围路由，并写明唯一性边界、超容量回落和旧整数索引的范围行为。

## Impact

代码面是二级键派生、`__tables` 行尾的索引登记、`CREATE INDEX` 计划与回填、INSERT/UPDATE/DELETE/UPSERT 与恢复重建、WHERE 路由和索引范围执行器。页类型、叶条目 38 字节和内部分隔 36 字节不变。主键与唯一索引的 `Value::to_key` 不变。

体系依据：`.agents/docs/tasks.md` 的 MS39；`.agents/memory/improvements.md` 的 I085 后半；项目模型 M03、M19、M20。M20 的「范围外缺陷不在当前变更里修」被本次目标覆盖：实施中新发现的实质缺陷先登记，再在本变更里增加一轮解决。初始计划不预编这些缺陷。

相关行为域：`sql-secondary-indexes`、`index-key-encoding-evaluation`。后者不改条款。生产格式仍是 MS38 选定的 32 字节定长键，条目布局没有换成变长编码。

## 场景草图

| 场景 | 前置状态 | 动作 | 结果与失败边界 |
|---|---|---|---|
| S01 组合等值 | 表上有 INT 与字符串列，含重复值、NULL 和超长字符串 | `CREATE INDEX` 多列，再按全部索引列等值查询 | 编码能放下的行经索引命中，结果与建索引前的扫描相同。任一列为 NULL 或整键超过 32 字节的行不入树，查询仍返回正确行 |
| S02 新整数范围 | 新建单列 INT 二级索引，值含负数、0 和边界 | `WHERE` 使用 `<`、`<=`、`>`、`>=` 或 `BETWEEN` | 计划点名该索引。负数按数值序落入正确的一侧。结果与全表扫描相同 |
| S03 旧整数索引 | 升级前已存在的单列 INT 二级索引 | 等值查询和范围查询 | 等值仍命中原行。范围仍走扫描，不按旧的大端字节序切范围 |
| S04 字符串范围 | 已有或新建的字符串二级索引，含空串、共享前缀、内部零字节和超长值 | 对可编码字面量做范围查询 | 树内键按字符串序返回。超长值由补扫纳入，不截断、不漏行、不把不同字符串并成同一个键 |
| S05 组合前缀 | 全 INT 组合索引 `(a, b)` | `a = 1`、`a > 1`、`a = 1 AND b > 2` | `(1, MAX)` 不属于 `a > 1`。`(2, MIN)` 不属于 `a = 1 AND b > 2`。结果与扫描相同 |
| S06 写入与恢复 | 组合索引已建立 | INSERT、改键、NULL 与超长之间转换、DELETE、回滚、未决 WAL 后重开 | 条目与存活行一致。失败和回滚不留下半截键。干净重开后查询不变 |
| S07 唯一性边界 | 表已有整数主键 | `CREATE UNIQUE INDEX`、表级组合 UNIQUE、五列以上全 INT 索引、表达式或带 WHERE 的索引 | 计划期点名拒绝，零副作用。组合二级索引允许重复整键 |
| S08 不路由的谓词 | 可路由索引已存在 | 参数、限定列、OR、额外无关谓词、非前缀列上的范围、类型不匹配 | 保持现有扫描或现有错误，不因为索引存在而少行 |
| S09 删列与删索引 | 组合索引引用其中一列 | `DROP COLUMN` 该列；另测 `DROP INDEX` | 被引用列拒绝删除。删索引后查询回到扫描，行集不变 |
| S10 运行形态 | 旧库、内存库、只读库、加密库、附加库 | 在各形态能到达的语句上查询或写入 | 只读仍拒绝建索引。附加库仍拒绝 `CREATE INDEX`。旧库打开不改写已有索引页。主键和 UNIQUE 行为不变 |

正常路径、拒绝、边界、写入与恢复的组合，以及取消和兼容都有对应场景。并发仍用现有的索引写单元和写侧闸门，不新增并发 DDL 承诺。

## Non-goals

- 表达式索引、部分索引、`IF NOT EXISTS`、`INCLUDE`、访问方法声明。
- 字符串或组合主键，字符串或组合 UNIQUE，`CREATE UNIQUE INDEX`。
- 改变主键或唯一索引的键字节，或在打开旧库时重写已有索引。
- 变长页格式、索引键溢出页、截断或哈希摘要键。
- I025 节点锁、I029 瘦内部节点、代价模型和 JOIN 重排。
- 预先编造尚未出现的缺陷，或把 MS41–MS44 纳入本变更。

## 已关闭的行为选择

这些选择会改变查询计划和键字节。里程碑文本加上已经生效的 32 字节键、禁止截断和旧库可读，只留下下面这一组：

1. 范围结果必须等于全表扫描。字符串超长值按 MS38 不入树。只扫树会漏掉落在范围内的超长值，所以字符串范围在树范围之外还要补上「键派生为空」的可见行。不改页格式、也不截断，这是能让字符串范围既路由又与扫描相等的做法。
2. 现有单列 INT 键是大端字节，负数排在正数之后。对这种键做字节范围会与数值序不一致。只读打开不能重写页面，所以旧 INT 索引保持原字节，范围继续扫描，等值保持现状。
3. 新建的 INT 二级索引要把符号位翻转，范围才能包含正确的负数。这仍是 8 字节，放在现有 32 字节键里，不采用 MS38 已否决的变长整数编码。
4. 组合键按列序拼接。全 INT 且超过 4 列时 8×N 已大于 32，没有任何行能入树，计划期拒绝。含字符串的组合仍可建，放不下的行不入树。
5. 唯一性边界是保持拒绝，不新增组合 UNIQUE。I085 要求评估唯一性，同时要求不一次开放全部索引语法。

打开旧库时重写全部二级索引被排除：只读打开不能写页，也会改变 MS38 已经承诺的旧整数索引字节。只做整数范围、让字符串范围永远扫描，则范围谓词没有覆盖已经交付的字符串索引，I085 的范围访问不能关闭。

## Rollback

本阶段只增加变更文档。实施后退回本分支的代码后，新建立的组合索引和符号位翻转的整数索引不再被语句维护；已经写入的树仍是现有 0x01/0x02 页。升级说明必须指出这些树不会被旧代码按原语义维护。主键、唯一索引和升级前的单列索引字节没有被本设计改写，因此不需要全库迁移。不支持从新目录尾段降级后继续维护新索引。
