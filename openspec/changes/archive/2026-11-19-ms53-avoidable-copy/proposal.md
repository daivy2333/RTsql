## Why

里程碑 MS53（`.agents/docs/tasks.md`）要求复制、分配和行锁争用都有测量，并且只有被测量证明值得改的那一处进入实现，SQL 结果不变，其余保留原实现。

这三处不能用同一次测量判断：复制看的是执行器里整组克隆的耗时，分配器要换全局分配器才能比较，行锁表现在不在 SQL 路径上。里程碑的拆分信号因此生效，分成多个变更，不新编号。本次只做复制。来源是 I020。分配器是 I066，行锁是 I050，都不是本次的实现对象。

I020 要求先测量并减少可避免的整组复制，再评估 `Value` 字符串的 `Arc`/`Cow`。JOIN 流水处理不在 I020，也不在本次。

## What Changes

- 用一次 release 测试驱动四个执行器，打印整组克隆循环的纳秒和对应执行器排空的纳秒。测试不断言是否达到 10%。
- 整组克隆达到该执行器耗时的 10% 时，只改打印结果里份额最大的那一处。SQL 结果、错误文本和 SQLSTATE 不变。
- 没有任何整组克隆达到 10% 时，再把字符串克隆循环和哈希连接执行器比较。达到 10% 则只把 `Value::String` 的负载改成 `Arc<str>`。仍达不到则产品代码保持测量前的状态。
- 两种结局都不改分配器、`RowLockTable`、可见性或锁等待的对外错误。

10% 沿用 MS47 已用过的整数比较：`clone_ns * 10 >= executor_ns`。等于 10% 算达到。门槛在看到数字之前写死，不在看到数字之后改。

### 场景草图

1. 哈希连接的匹配桶。前置：左 50 行、右 50 行，键为 `0..50` 的整数，一对一等值。动作：排空 `JoinExecutor`。结果：50 行；探测按桶下标取行，不克隆整桶，所以 `hash_bucket_clone_ns` 为 0，`hash_executor_ns` 大于 0。失败边界：执行器耗时为 0，或探测既不是按下标取行、也不是克隆整桶时，测量无效，不得记成未达到。
2. 嵌套循环的组合行。前置：左右各 50 行，内连接，谓词为恒真，每一对都会求值。动作：排空 `NestedLoopJoinExecutor`。结果：2500 行；打印 `nlj_clone_ns` 与 `nlj_executor_ns`。失败边界：执行器耗时为 0，或组合循环的访问次数不是 2500。
3. 排序交出。前置：100 行按整数键逆序送入，`ORDER BY` 升序。动作：排空 `SortExecutor`。结果：100 行，首行键为 0，末行键为 99；打印 `sort_clone_ns` 与 `sort_executor_ns`。失败边界：执行器耗时为 0，或交出的不是这 100 行。
4. 排序合并交出。前置：左右各 50 行，整数键一对一等值。动作：排空 `SortMergeJoinExecutor`。结果：50 行；打印 `smj_clone_ns` 与 `smj_executor_ns`。失败边界：执行器耗时为 0，或结果不是 50 行。
5. 字符串克隆。前置：同一测试里已经有哈希连接执行器的耗时。动作：把 50 个 `customer_{i}` 字符串各克隆一次并计时。结果：打印 `string_clone_ns`。失败边界：哈希连接执行器耗时为 0。本场景的数字只在四个整组克隆都未达到 10% 时才参与裁定。
6. 裁定。前置：上面的纳秒数都有效。动作：用 `u128` 做 `clone_ns * 10 >= executor_ns`。结果：整组克隆里达到门槛的，取 `clone_ns` 最大的一处进入实现；都未达到时，字符串克隆达到门槛则只改 `Value::String`；否则不改产品代码。失败边界：乘法溢出时停止，不记成未达到。多处 `clone_ns` 相等时，依次取嵌套循环、排序合并、排序、哈希桶。
7. 实现之后结果不变。前置：裁定已经点名一处。动作：只改那一处。结果：同一输入的行多重集合、排序次序、比较结果和错误文本与改前一致。失败边界：为了去掉克隆必须改可见性、锁等待的对外错误，或必须改谓词 trait 的错误文本时，停止，不改。
8. 未达到。前置：整组克隆和字符串克隆都低于 10%。动作：结束本次实现。结果：产品代码与测量前一致，变更记录里有全部打印数字和「保留原实现」。
9. 分配器与行锁不动。前置：本次 diff 不包含 `Cargo.toml` 的分配器依赖，也不修改 `src/transaction/row_lock.rs`。动作：不引入 `jemalloc`/`mimalloc`，不把 `RowLockTable` 换成 `DashMap`。结果：这两处仍是原实现。它们的测量是后续变更，不在本次。

### 已经选定的行为

- 本次只测量和可能修改复制。分配器与行锁另开变更。
- 先看整组克隆。有一处达到 10% 就只改那一处，不再改 `Value::String`。
- 整组克隆都未达到时，才允许字符串的 `Arc<str>` 成为那一处。
- 哈希连接的匹配桶当前按下标取行。测量确认这一点；确认之后该处的克隆耗时记 0，不为此再改代码。
- 测量使用执行器入口和一次 release 测试，不新增诊断指标，不新增判定脚本。

## Capabilities

### New Capabilities

- `avoidable-copy`：整组克隆与字符串克隆的耗时测量，以及恰好一处达到 10% 时的实现。未达到时不改产品代码。

### Modified Capabilities

- 无。查询结果、错误文本、SQLSTATE、诊断阶段、文件格式和锁等待错误保持现状。达到门槛并实现之后，这些对外结果仍然保持。

## Impact

- 测量只加 `tests/ms53_copy_measure.rs`，不改产品代码。
- 嵌套循环达到门槛时，改 `src/executor/nested_loop_join.rs` 的组合行构造。谓词仍看到左列在前、右列在后的行。
- 排序或排序合并达到门槛时，改 `src/executor/sort.rs` 或 `src/executor/sort_merge_join.rs` 的交出克隆。
- 字符串达到门槛时，改 `src/executor/value.rs` 的 `Value::String` 负载，以及仓内构造和匹配这个负载的位置。磁盘上的元组标签不改。
- 不改 `Cargo.toml` 的依赖，不改 `src/transaction/row_lock.rs`。
- 引用：MS53、I020、M19、M21、M22。本次每次测试调用都带 `--test-threads=1`。全量不在测量轮。字符串表示若进入实现，验证范围写在 `tasks.md` 的对应轮次，不在测量轮跑全量。

## 回滚

未达到时没有产品改动，无需回滚。达到后的改动不改文件格式。嵌套循环、排序或排序合并的交出方式可以按站点退回原来的克隆。`Arc<str>` 可以退回 `String`，已有库文件不用迁移。
