## 3. 未完成部分详解

### 3.1 T2.3 惰性 `set_all_visible`

**现状**：`set_all_visible` 方法已实现（`buffer_pool.rs:344`），但**零调用者**。

**问题**：何时设置 `all_visible = true`？

**设计意图**（ADR-011）：
> 扫描路径发现页上所有行都已提交时，惰性设置 `all_visible = true`，后续扫描可跳过逐行检查。

**竞态条件**（Plan Agent 指出）：
```
时间线：
T1: 扫描器发现页上所有行已提交 → 准备 set_all_visible
T2: 并发 INSERT 在同一页写入新行（uncommitted）
T3: 扫描器 set_all_visible(true)
T4: 另一个扫描器看到 all_visible=true → 跳过逐行检查 → 返回未提交行！
```

**解决方案选项**：

| 方案 | 描述 | 复杂度 | 风险 |
|------|------|--------|------|
| A: 扫描结束时设置 | 扫完页后 if all_committed then set_all_visible | 低 | 有竞态窗口 |
| B: 页级锁保护 | 扫描期间持有页读锁，INSERT 持页写锁 | 中 | 可能引入锁争用 |
| C: 版本号校验 | `set_all_visible` 时检查 `slot_count` 未变 | 低 | 需额外存储 |
| D: 延后实现 | 当前延后策略，等更多使用数据 | - | 正确性优先 |

**当前选择**：方案 D（延后实现）

### 3.3 DELETE 不更新数据页（额外问题）

**现状**：`DeleteExecutor::next` (`src/executor/delete.rs:41-85`) 只删除 B-tree 索引，不更新数据页。

**代码分析**：
```rust
// 第 63 行：只删索引
self.index_manager.delete(&self.key).await?;

// 没有任何数据页操作！
// 数据页上的 slot 和 version header 完整保留
```

**影响**：
- 全表扫描（DataScan）会返回已删除行（version header 未变）
- 只有通过索引查询才会正确返回"未找到"

**与 L028 记录一致**：
> DELETE 仅删 B-tree 索引不更新数据页 version header → 全表扫描仍可见已删除行

**修复建议**（不在 M21 原始范围，但相关）：
- 方案 A：DELETE 时更新 version header（标记 deleted_tx_id）
- 方案 B：DELETE 时设置 next_version 指向"已删除"标记
- 方案 C：GC 阶段清理（当前设计，但 GC 未实现）
