## 1. 问题定位

### 1.1 当前 ScanExecutor 的问题

**症状**：全表扫描性能落后 SQLite ~4x（snapshot.md 已知限制）

**根因分析**：当前 `ScanExecutor`（`src/executor/scan.rs:9`）采用 **Index→RowId→Data** 三步访问模式：

```rust
// scan.rs:48
let entries = self.table_meta.index_manager.scan_all().await?;
for (_key, row_id) in entries {
    // 每行：IndexManager.scan_all() → BTree遍历 → RowId
    // 然后：find_visible_version(row_id) → BufferPool.get_page → DataPage读取
    ...
}
```

**每行的 I/O 路径**：
1. `IndexManager.scan_all()` → BTree 叶节点遍历 → 获取 `(key, RowId)`
2. `find_visible_version(row_id)` → BufferPool 页访问 → 版本链遍历
3. `deserialize_value_refs` → tuple 数据反序列化

**问题**：即使 BTree 叶节点已包含所有 RowId，仍需额外访问数据页。每行至少 **2 次页访问**（索引页 + 数据页）。

### 1.2 对比 SQLite 全表扫描

SQLite B-Tree 页格式：
- 数据直接存储在 B-Tree 叶节点（Table B-Tree）
- 全表扫描只需遍历叶节点链表，**每行 1 次页访问**

RTsql 设计差异：
- B-Tree 叶节点只存 `(key, RowId)`（Index B-Tree）
- 数据存储在独立的数据页（SlottedPage 链表）
- 分离设计导致全表扫描开销翻倍

## 2. 现有架构分析

### 2.1 数据页链表结构

**SlottedPageHeader**（`src/storage/page_format/slotted_page.rs:17`）：

```rust

    pub page_type: u8,          // 0x03=Data
    pub slot_count: u16,        // 当前 slot 数量
    pub free_space_offset: u16, // 数据区起始偏移
    pub next_page_id: u32,      // 下一个数据页 ID（链表指针）
    pub next_logical_id: u16,   // 下一个 logical ID

}
```

**关键发现**：
- `next_page_id: u32` **已存在**，支持数据页链表遍历
- `TableMeta.data_page_head: PageId`（`src/storage/data/table_manager.rs:51`）指向首个数据页
- `TableMeta.data_page_tail: Mutex<PageId>`（`src/storage/data/table_manager.rs:52`）指向末尾数据页（用于追加新页）

**数据页链表已就绪，但未被利用**：当前 ScanExecutor 不使用 `data_page_head`，而是通过索引遍历。

### 2.2 Planner 扫描方式选择

**build_query**（`src/parser/planner.rs:393`）扫描方式选择逻辑：

```rust
// line 468-514
if let Some(where_expr) = &select.selection {
    if let Some(key) = self.extract_pk_from_where(&table_name, where_expr)? {
        if self.is_simple_pk_equality(&table_name, where_expr)? {
            // 简单 PK 等值条件 → IndexScan
            PhysicalPlan::IndexScan(IndexScanNode { table_name, key, columns })
        } else {
            // 复杂 WHERE 含 PK → Filter over Scan
            PhysicalPlan::Filter(FilterNode { input: base_plan, predicate, table_name })
        }
    } else {
        // 非 PK WHERE → Filter over Scan
        PhysicalPlan::Filter(FilterNode { input: base_plan, predicate, table_name })
    }
} else {
    // 无 WHERE → 全表 Scan
    base_plan  // PhysicalPlan::Scan(ScanNode)
}
```

**选择规则**：
| 条件 | 扫描方式 | 备注 |
|------|---------|------|
| `pk = value`（简单等值） | `IndexScan` | 主键点查，1 次 BTree search |
| `pk = value AND other_cond` | `Filter(Scan)` | 不优化 PK，走全表扫描 + 过滤 |
| 无 WHERE | `Scan` | 全表扫描（`index_manager.scan_all()`） |
| 非 PK WHERE | `Filter(Scan)` | 全表扫描 + 过滤 |

**问题**：无论有无 WHERE，都走 `Scan` → `index_manager.scan_all()` → BTree 遍历，未利用数据页链表。

### 2.4 ScanExecutor 执行流程

**src/executor/scan.rs**：

```rust
pub struct ScanExecutor {
    table_meta: Arc<TableMeta>,
    buffer_pool: Arc<BufferPool>,
    schema: Vec<ColumnType>,
    snapshot: Option<Snapshot>,
    results: Vec<Vec<Value>>,  // 全部结果预加载
    index: usize,
    executed: bool,
}

impl Executor for ScanExecutor {
    async fn next(&mut self) -> Result<Option<ExecResult>> {
        if !self.executed {
            self.executed = true;
            // 一次性加载所有结果
            let entries = self.table_meta.index_manager.scan_all().await?;
            for (_key, row_id) in entries {
                // MVCC 可见性检查 + 反序列化
                let values = find_visible_version(row_id, snapshot, |bytes| {
                    deserialize_value_refs(bytes, &self.schema)
                        .map(|vrs| vrs.iter().map(|vr| vr.to_value()).collect())
                }).await?;
                self.results.push(values);
            }
        }
        // 返回预加载结果
        if self.index < self.results.len() {
            let values = self.results[self.index].clone();
            self.index += 1;
            Ok(Some(ExecResult::Row(values)))
        } else {
            Ok(None)
        }
    }
}
```

**问题**：
1. `scan_all()` 一次性遍历 BTree，无流式处理
2. `results: Vec<Vec<Value>>` 预加载全部结果，内存压力大
3. 每行需要 `find_visible_version` → BufferPool 页访问

## 3. M19 优化方案

### 3.1 T1: DataScanExecutor 顺序扫描数据页

**目标**：跳过索引层，直接遍历数据页链表

**新增 PhysicalPlan 节点**：

```rust
// src/executor/plan.rs
pub enum PhysicalPlan {
    ...
    /// 数据页直接扫描（跳过索引）
    DataScan(DataScanNode),
}

pub struct DataScanNode {
    pub table_name: String,
    pub columns: Vec<String>,
}
```

**新增 DataScanExecutor**：

```rust
// src/executor/data_scan.rs
pub struct DataScanExecutor {
    table_meta: Arc<TableMeta>,
    buffer_pool: Arc<BufferPool>,
    schema: Vec<ColumnType>,
    snapshot: Option<Snapshot>,
    current_page_id: Option<PageId>,  // 当前数据页
    current_slot_index: usize,         // 当前页内 slot 索引
}

impl Executor for DataScanExecutor {
    async fn next(&mut self) -> Result<Option<ExecResult>> {
        loop {
            // 当前页耗尽 → 跳转下一页
            if self.current_page_id.is_none() {
                return Ok(None);
            }

            let page_id = self.current_page_id.unwrap();
            let guard = self.buffer_pool.get_page(page_id).await?;
            let data = guard.page_data();
            let page_ref = SlottedPageRef::new(&data);

            // 遍历当前页剩余 slots
            while self.current_slot_index < page_ref.slot_count() {
                let slot = page_ref.get_slot(self.current_slot_index)?;
                self.current_slot_index += 1;

                let row_id = RowId::new(page_id, slot.logical_id);
                let slot_data = page_ref.get_slot_data(&slot);

                // MVCC 可见性检查（从 slot_data 解析 VersionHeader）
                if self.is_visible(slot_data)? {
                    let values = deserialize_value_refs(slot_data, &self.schema)?;
                    return Ok(Some(ExecResult::Row(values.iter().map(|vr| vr.to_value()).collect())));
                }
            }

            // 当前页结束 → next_page_id
            let next_page = PageId(page_ref.header().next_page_id as u64);
            self.current_page_id = if next_page.0 == 0 { None } else { Some(next_page) };
            self.current_slot_index = 0;
        }
    }
}
```

**预期收益**：
- 每行 **1 次页访问**（数据页），跳过索引页
- 流式处理，无需 `results: Vec<Vec<Value>>` 预加载
- 页内 slots 连续访问，局部性更好

```rust
fn has_pk_equality(&self, table_name: &str, expr: &Expr) -> Result<bool, PlanError> {
    // 递归检查 AND 组合中是否有 pk = value
    match expr {
        Expr::BinaryOp { left, op: BinaryOperator::Eq, right } => {
            // 单个 pk = value 条件
            self.is_pk_column(table_name, left) || self.is_pk_column(table_name, right)
        }
        Expr::BinaryOp { left, op: BinaryOperator::And, right } => {
            // AND 组合：检查任一分支
            self.has_pk_equality(table_name, left)? || self.has_pk_equality(table_name, right)?
        }
        _ => Ok(false),
    }
}
```

## 6. 风险与限制

### 6.1 MVCC 版本链处理

**挑战**：数据页 slot 存储 **最新版本**，历史版本在版本链中（可能跨页）。

**当前版本链结构**（`src/storage/data_page.rs`）：
- 每个 tuple 前缀 `VersionHeader`（16B）：
  - `begin_tx_id: u64`
  - `commit_tx_id: u64`（未提交 = 0）
  - `next_version: Option<RowId>`（指向旧版本）

**DataScanExecutor 需处理**：
1. 读取 slot → 解析 VersionHeader
2. 检查 `commit_tx_id` 是否对 snapshot 可见
3. 不可见 → 沿 `next_version` 遍历版本链

**版本链遍历仍需页访问**：历史版本可能在不同数据页。

### 6.2 数据页无 RowId 映射

**问题**：数据页 slot 只有 `logical_id`，无 `RowId` 直接对应。

**RowId 定义**（`src/storage/page_format/tuple.rs`）：
```rust
pub struct RowId {
    pub page_id: PageId,
    pub slot_id: u16,  // 即 logical_id
}
```

**解决**：DataScanExecutor 需自己构造 RowId：
```rust
let row_id = RowId::new(page_id, slot.logical_id);
```

### 6.3 已删除 slot 处理

**问题**：GC 删除 slot 后，`slot_count` 减少，但 `logical_id` 序号不连续。

**SlottedPage 现状**：
- `delete_slot` 移动 slots 填补空洞
- `logical_id` 是分配时递增的，删除后不重用

**DataScanExecutor 需处理**：
- 遍历 slots by `slot_count`（物理顺序）
- 每个 slot 的 `logical_id` 用于构造 RowId

### 6.4 性能预期验证

**预期 ~2x 提速**的前提：
- 无版本链遍历（大部分读已提交最新版本）
- 无 WHERE 过滤开销
- 页访问局部性收益

**实际收益可能受影响**：
- MVCC 版本链遍历（如果大量未提交/旧版本）
- 页缓存命中率（BufferPool 已缓存索引页）
- 数据页碎片化（`next_page_id` 链表不连续）

## 8. 总结

**M19 核心改进**：从 Index→RowId→Data 三步访问，简化为 Data 页直接遍历。

**架构优势**：
- 数据页链表结构已存在（`next_page_id`）
- M20/M36 零拷贝基础设施可直接复用
- 改动范围小（新增 DataScanExecutor + Planner 选择逻辑）

**预期收益**：
- 全表扫描 ~2x 提速（页访问次数减半）
- 流式处理减少内存压力
- 与 SQLite Table B-Tree 设计对齐

**下一步建议**：
1. 先实现 T1（DataScanExecutor 纯扫描）+ 单元测试
2. 再加入 MVCC 可见性检查
3. T2/T3 Planner 改造
4. T4 性能验证（criterion 对比）
